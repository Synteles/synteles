# Governance

Synteles is currently maintained as a founder-led open-source project.

The governance model is intentionally lightweight while the project is in its early stage. The goal is to keep decision-making clear, transparent, and maintainable as the community forms.

## Project Maintainer

The current project maintainer is:

```text
Emin Askerov
```

The maintainer is responsible for:

- Project direction and roadmap
- Repository administration
- Reviewing and merging pull requests
- Release management
- Security response coordination
- License and trademark decisions
- Community standards enforcement
- Documentation and contributor experience

## Decision-Making

During the early phase of the project, final decisions are made by the maintainer.

Input from users and contributors is welcome through:

- GitHub issues
- Pull requests
- GitHub discussions, if enabled
- Design proposals
- Documentation feedback

The maintainer will consider technical quality, project direction, security impact, maintainability, and user value when making decisions.

## Significant Changes

For significant changes, contributors should open an issue or proposal before implementation.

Significant changes may include:

- Public APIs
- Workflow definition formats
- Runtime architecture
- Connector framework changes
- Security-sensitive functionality
- Deployment model changes
- Data model or persistence changes
- Licensing or governance changes
- Breaking changes to user-facing behavior

A proposal should explain:

- The problem being solved
- The proposed approach
- Alternatives considered
- Expected impact on users, contributors, and maintainers
- Any security, compatibility, or migration implications

## Pull Request Review

Pull requests are reviewed by the maintainer.

A pull request may be merged when it:

- Aligns with the project direction
- Is technically sound
- Is reasonably tested
- Does not introduce unacceptable security or maintenance risk
- Includes documentation where needed
- Keeps scope focused and reviewable
- Complies with the project license and contribution requirements

The maintainer may request changes, close stale pull requests, or defer work that is not aligned with current priorities.

## Releases

Releases are created by the maintainer.

Before `v1.0`, Synteles should be considered early-stage software. Breaking changes may occur.

Release notes should document:

- New features
- Bug fixes
- Breaking changes
- Migration notes
- Known limitations
- Security-relevant changes, where appropriate

The project intends to follow semantic versioning once public APIs, workflow definitions, and runtime interfaces become stable.

## Roadmap

The roadmap is maintained by the project maintainer and may evolve based on:

- Technical priorities
- User feedback
- Community contributions
- Security considerations
- Enterprise deployment requirements
- Maintainer capacity

The roadmap is not a commitment to deliver specific features by specific dates.

## Maintainer Rights and Responsibilities

The maintainer may:

- Accept or reject contributions
- Prioritize issues and roadmap items
- Create releases
- Manage repository settings
- Enforce the Code of Conduct
- Update project governance as needed
- Make security-related decisions
- Protect project trademarks and brand assets

The maintainer should aim to:

- Be transparent about major project decisions
- Review contributions respectfully
- Explain rejections or deferrals where practical
- Keep the project usable, secure, and maintainable
- Encourage constructive participation

## Becoming a Maintainer

As the project grows, contributors who consistently provide high-quality contributions may be invited to become maintainers.

Maintainer responsibilities may include:

- Reviewing pull requests
- Triaging issues
- Maintaining specific components
- Improving documentation
- Supporting releases
- Helping with community discussions
- Supporting security response processes

Maintainer access is granted at the discretion of the existing maintainer.
